## 0. Recommendation (read this first)

1. **Switching is mostly "stop typing `clauded`."** It is not a config project. On every machine I checked, the CLI is new enough (ASIAGO 2.1.301; TILSIT and MIMOLETTE 2.1.296) that plain `claude` already starts in auto mode. Auto mode is the built-in default for interactive terminal sessions from v2.1.283 (PM#which-mode-a-session-starts-in). No settings file sets `permissions.defaultMode` (checked: `~/.claude/settings.json`, `~/.claude/settings.local.json`, and ASIAGO's `machine-settings.json`; `grep -c defaultMode` = 0 on TILSIT and MIMOLETTE). YOLO comes only from the `--dangerously-skip-permissions` flag in the `clauded` / `megaclauded` / `suclauded` aliases. The transcripts agree: 6 interactive sessions on ASIAGO (v2.1.281–2.1.293) recorded `auto` as their first mode with no flag, which fits the Max-plan auto default the docs describe for pre-2.1.283 versions. 8 sessions in the last 60 days ran at least partly in auto mode, and the scan found 0 classifier denials in them. 223 tool calls is too small a sample to prove anything.
2. **Tune it before you rely on it.** Add one `autoMode.environment` block that names the three GitHub owners, the LAN hosts, and the secret stores. Add a small `autoMode.allow` list for routine actions the classifier blocks by default, mainly `gh pr merge`, which the merge-lock gates. Keep `"$defaults"` in every list. Section 4.2 has a concrete draft.
3. **Add hard limits as `permissions.deny`/`ask`, not as classifier prose.** Deny rules run before the classifier in every mode, including bypass. Your existing hook chain already covers the workflow gates: main-commit, merge-lock, `--no-verify`, secret-leak, and text approval. Auto mode adds what the hooks do not cover: destructive git, `rm -rf` on unknown targets, force push, exfiltration, and `curl | bash`.
4. **Roll out in phases.**
   - Phase 1: pilot on ASIAGO interactive sessions only, through `~/.config/claude-code/machine-settings.json`. It is untracked, and the wrapper applies it only to interactive sessions (`lib/machine-settings.sh:14-17`).
   - Phase 1 also adds a `PermissionDenied` logging hook, so you have one week of real denials before you tune.
   - Phase 2: move the tuned `autoMode` block into claude-config `settings.json` as a PR.
   - Phase 3: retire or rename `clauded`.
   - Keep `clauded` available for overnight runs where nobody can answer a prompt, until the denial log shows those runs are clean.
5. **Main risk: unattended stalls.** Three consecutive blocks, or 20 in total, pause auto mode, and the session goes back to prompting (PM#when-auto-mode-falls-back). An interactive session then waits for a human. Remote Control is on (`settings.json:198`), and it forwards permission prompts to the phone (<https://code.claude.com/docs/en/remote-control>, "Forwarded dialogs expire": prompts stay open until answered). Turn on "Push when actions required" in `/config` so that a stall shows up as a push notification.

## 2. What auto mode is (Claude Code 2.1.301 docs)

### 2.1 Enabling it

- Flag: `--permission-mode auto`. Choices from `claude --help`: `acceptEdits`, `auto`, `bypassPermissions`, `manual`, `dontAsk`, `plan`.
- Setting: `permissions.defaultMode: "auto"`. This works only from `~/.claude/settings.json`, from a `--settings` file, or from managed settings. In a project's `.claude/settings*.json` it is ignored (PM#which-mode-a-session-starts-in; <https://code.claude.com/docs/en/agent-view#permission-mode>).
- Built-in default: `auto` for interactive terminal sessions on v2.1.283 or later. For `claude -p`, the default is `default` in sessions that fetch feature flags (PM#which-mode-a-session-starts-in).
- Precedence: a flag (`--permission-mode` or `--dangerously-skip-permissions`) beats `defaultMode`, which beats the built-in default. So `clauded` always wins over any setting.
- Mid-session: Shift+Tab cycles modes. Bypass appears in the cycle only if the session started with it enabled. A Bash prompt in Manual mode offers "Yes, and switch to auto mode" (PM#switch-permission-modes).
- Requirements: all plans. Supported models are Opus 4.6+, Sonnet 4.6+, Haiku 5.5, and Fable on the Anthropic API. An org can turn it off with `permissions.disableAutoMode` (PM#eliminate-prompts-with-auto-mode).

### 2.2 How it decides (PM#how-the-classifier-evaluates-actions)

Each action takes the first step that matches:

1. Allow, ask, and deny rules resolve first, with these exceptions:
   - Protected-path writes still go to the classifier.
   - Critical-path `rm` is never auto-approved by a rule.
   - Content-matching ask rules always prompt.
2. Read-only actions and file edits in the working directory are auto-approved, with two exceptions: protected paths, and the first read outside the working directories, which prompts once.
3. Everything else goes to a classifier model, Sonnet 5 by default rather than your session model.
   - The classifier sees user messages, the tool calls, and CLAUDE.md. It does **not** see tool results, which defends against prompt injection.
   - A server-side probe also scans tool results.
4. When the classifier blocks, Claude gets the rule name, for example `[Data Exfiltration]`, and tries another way.

On entering auto mode, broad allow rules are dropped: `Bash(*)`, wildcarded interpreters such as `Bash(python*)`, package-manager run commands, `Agent` allow rules, and `Monitor` allow rules. Narrow rules such as `Bash(npm test)` stay. `autoMode.classifyAllShell: true` sends every shell command to the classifier anyway (AMC#route-all-shell-commands-through-the-classifier).

### 2.3 Default rule set (from `claude auto-mode defaults` on 2.1.301)

- 17 `allow` exceptions. Relevant ones: Local Operations, Read-Only Operations, Declared Dependencies, Standard Credentials, Git Push Destination (any branch of the session's repo, default branch included), Memory Directory, CLAUDE.md Content, Multi-Agent Coordination, Scheduled-Task Fires.
- 72 `soft_deny` rules. A user message that names the action and its specifics can clear one.
- 1 `hard_deny` rule: Data Exfiltration.
- 21 `environment` slots, mostly "None configured".
- The doc's summary list of default blocks (PM#what-the-classifier-blocks-by-default) includes:
  - force push
  - `git reset --hard`, `git checkout -- .`, `git restore .`, `git clean -fd`, `git stash drop`
  - amending a commit not made in this session
  - merging a PR no human approved
  - writing to a secret manager
  - `curl | bash`
  - launching an agent with `--dangerously-skip-permissions`
  - printing a live credential
  - `rm -rf "$VAR"` when `$VAR` is not assigned in the visible transcript
  - opening PRs against another org
  - publishing sensitive details in PR or issue bodies on public repos

### 2.4 Tuning knobs

| Knob | Where | Notes |
|---|---|---|
| `permissions.allow` / `ask` / `deny` | any settings file | Resolve before the classifier. Deny applies in every mode. Ask always prompts, even in auto. They match the command **as written**, so `Bash(git push *)` does not match `git -C dir push` (AMC#add-a-human-checkpoint). |
| `autoMode.environment` | `~/.claude/settings.json`, `--settings`, or managed only; **not** project settings (AMC#where-the-classifier-reads-configuration) | Prose entries that name trusted source control, domains, services, and secret stores. Keep `"$defaults"`. |
| `autoMode.allow` / `soft_deny` / `hard_deny` | same scopes | Prose. Leaving out `"$defaults"` **replaces** the built-in list (AMC#override-the-block-and-allow-rules). |
| `autoMode.classifyAllShell` | same | Suspends all Bash allow rules while in auto mode. |
| CLAUDE.md | normal | The classifier reads it. "Never force push" steers both Claude and the classifier. |
| Conversation statements | per session | "Don't push" is a block signal. Naming an action and its specifics clears one soft block. Compaction can lose either (PM#boundaries-you-state-in-conversation). |
| `/auto-mode-setup` | interactive | Drafts environment entries from the project and recent sessions. Writes to `~/.claude/settings.json`, which here is the tracked claude-config file. |
| `claude auto-mode config` / `defaults` / `critique` / `reset` | CLI | Inspect, review, or reset the effective rules. |
| `PermissionDenied` hook | hooks | Fires only in auto mode and gets `tool_input` + `reason`. Can return `retry: true` (<https://code.claude.com/docs/en/hooks#permissiondenied>). |
| PostToolUse `classifierContext` | hooks | Sends a note about a tool result to the classifier, which otherwise never sees results. |

### 2.5 Interaction with PreToolUse hooks

- PreToolUse hooks run before the permission decision, for every tool, in every mode (<https://code.claude.com/docs/en/permissions#extend-permissions-with-hooks>). Your hook chain therefore keeps working unchanged under auto mode, as it does under bypass now.
- A hook `deny` (exit 2) is always honored.
- A hook `ask` forces a prompt in auto mode (v2.1.211+).
- A hook `allow` cannot override deny or ask rules, and it cannot approve a critical-path `rm` (PM#critical-paths).
- An installed mod that handles `tool.check` can approve before the classifier, and can override a non-managed PreToolUse block. Worth knowing; not relevant today.

### 2.6 Subagents and background sessions

- **Subagents.** The classifier checks a subagent at three points (PM, "How auto mode handles subagents"):
  1. at spawn, on the task description;
  2. on every action, with the parent's rules;
  3. on the final report. A flagged report arrives with a security warning prepended.

  Frontmatter `permissionMode` is ignored.
- **Background subagents.** Their permission prompts surface in the main session (<https://code.claude.com/docs/en/sub-agents#run-subagents-in-foreground-or-background>).
- **`claude --bg` sessions.** They start the way a new `claude` session in that directory would (<https://code.claude.com/docs/en/agent-view#permission-mode>). On 2.1.283+ that means auto.
- **`claude -p`.** It starts in `default` unless `--permission-mode` is passed. With `--permission-mode auto --permission-prompts none`, anything that would prompt is denied, and the run continues instead of hanging (<https://code.claude.com/docs/en/headless>).

### 2.7 Known limits

- **Not a guarantee.** "Auto mode reduces permission prompts but does not guarantee safety" (PM#eliminate-prompts-with-auto-mode).
- **Fallback thresholds.** 3 blocks in a row or 20 in total pause auto mode and return to prompting. The thresholds are not configurable (PM#repeated-block-thresholds).
- **Critical-path `rm`** (`~`, cwd, `"$D"/*`, and similar) gets a 2-minute prompt countdown in the terminal, then a deny. After three unanswered countdowns, further ones are denied at once (PM#time-limits-and-denials-in-auto-and-bypasspermissions-modes).
- **Protected paths** (`.git`, `.config/git`, `.claude` with exceptions, `.bashrc` and similar, `.gitconfig`, `.mcp.json`) go to the classifier.
  - Allow rules cannot pre-approve them.
  - **Special case:** when a settings file is a symlink, a write to its target prompts *even when an allow rule matches* (PM#protected-paths). `~/.claude/settings.json` is a symlink to `/Users/andrewrich/Developer/claude-config/settings.json` (`ls -la`), so every edit of claude-config `settings.json` will prompt.
- **First out-of-cwd read** with Read, Grep, or Glob prompts once. "Yes, and keep allowing" persists the answer (PM#first-read-outside-the-working-directories).
- **Plan mode.** `useAutoModeDuringPlan: false` (`settings.json:206`) means plan mode prompts for every non-read-only command instead of using the classifier.
- **Ask rules match the command as written.** `git -C` and `gh -R` forms slip past prefix rules. The existing hooks parse full text and do not have this gap.
- **Cost and latency.**
  - Every classified shell command adds one round-trip.
  - Server-side review folds into the session's model requests on direct Anthropic API connections, v2.1.271+ for Pro, Max, and Team (PM#server-side-classifier-review).
  - Classifier calls count toward usage on Enterprise and API accounts (PM, "Cost and latency").
  - Which billing path your sessions take, and whether this touches the reviewer API-credit setup, is UNVERIFIED.

### 3.2 `hook-block-all.sh` chain, in order (`scripts/hook-block-all.sh:39-51`)

1. secret-leak: blocks commands that would print a live secret.
2. gate-dir-write: Bash writes to the approval dirs and policy files.
3. no-verify: `--no-verify`.
4. short-no-verify: `-n` on commit or push.
5. main-commit: commit on main or master.
6. personify: commit, PR, or issue text not visually approved.
7. commit-message: conventional-commit format pre-check.
8. merge-lock-authorize: agent may not run `merge-lock authorize`.
9. api-merge: REST/GraphQL merge that bypasses the gh wrapper.
10. gh-auth: `gh auth` token print or switch.
11. git-worktree: worktree subcommand policy.

Outside Claude Code, there are also the git pre-commit and pre-push AI review hooks (dotfiles), the gh wrapper (forced drafts off-org, merge through `pre-merge-review.sh`), and the `permissions.deny` list of 9 Asana write tools (`settings.json:185-197`).

### 3.3 What none of this blocks today

There is **no hook** for these:

- `rm -rf` of any kind
- force push
- `git reset --hard`, `checkout -- .`, `clean -fd`
- `curl | bash`
- `gh secret set`, keychain writes, `launchctl`
- SSH writes to other machines
- writes to `~/.bashrc`-type files
- exfiltration to arbitrary hosts

In bypass mode, only the model's judgment stops these, plus the critical-path `rm` circuit-breaker, which applies even in bypass (PM#critical-path-removals-in-each-permission-mode). This is the gap auto mode fills.

- **Rule syntax.** `Bash(x *)` is a prefix match. The space before the `*` is part of the rule, and `:*` is the equivalent suffix form (<https://code.claude.com/docs/en/permissions#permission-rule-syntax>). These rules match only commands that *begin* with the text. `git push origin --force` and `git -C x push --force` both slip past `Bash(git push --force *)`. The classifier's Git Destructive rule still catches those forms. If force push must prompt in every spelling, write a PreToolUse hook that returns `ask` after parsing the full command text, like `hook-block-main-commit.sh` does.
- **The merge `allow` is the main trade-off.** It makes the classifier trust your gh wrapper and merge-lock instead of its own Merge Without Review rule. That matches how you already work, because the lock is the approval. But a merge that bypasses the wrapper would no longer have a second net, for example `command gh`, a different PATH, or `GH_TOKEN` precedence (see the memory note on `GH_TOKEN` precedence). Keep `hook-block-api-merge.sh`.
- **Do not leave out `"$defaults"`** in any list. Without it, the whole built-in list is discarded (AMC#override-the-block-and-allow-rules).
- **Validate before relying on it.** Run `claude auto-mode config` to confirm the effective rules, and `claude auto-mode critique` to get feedback on the prose entries.

### 4.3 What would still prompt or block after tuning

1. Every edit to `/Users/andrewrich/Developer/claude-config/settings.json`. It is the symlink target of `~/.claude/settings.json`, so it always prompts (PM#protected-paths).
2. Writes under `.git/`, `.config/git/`, and `.claude/` (except worktrees, plans, and memory markdown), plus `.bashrc`-type files. These go to the classifier, and git hooks and shell profiles there hit Unauthorized Persistence or Self-Modification unless your message names the change.
3. The first Read, Grep, or Glob outside the cwd, once. Answer "Yes, and keep allowing".
4. Critical-path `rm` (`rm -rf ~/…$(…)`, `"$D"/*`, `rm -rf "$(pwd)"`): a 2-minute countdown, then deny.
5. Anything matching the `ask` rules above.
6. Post-merge `git checkout -- .` and `git clean -fd`, unless you say so in the session.
7. Plan mode: prompts for non-read-only commands while `useAutoModeDuringPlan` is `false`. Consider setting it to `true`.
8. Fleet-wide subagent tasks across many repos. The task description is classified at spawn time, so the Source control entry matters most here.

### 4.4 Risks

- **Unattended stalls (biggest operational risk).**
  - An interactive session left overnight can hit 3 consecutive blocks, pause auto mode, and then wait on a prompt.
  - Background subagents push their prompts to the main session, so a fleet run of parallel agents stalls on the parent.
  - Mitigation: Remote Control push for "actions required" (<https://code.claude.com/docs/en/remote-control>). Use `clauded` deliberately for runs you know are long and unattended until the denial log is clean.
- **False positives that trigger workarounds.** A blocked agent may look for another route. The default Auto-Mode Bypass rule treats that tunneling as a violation, but the agent's retries count toward the 3/20 thresholds.
- **Classifier blind spots.** The classifier does not see tool output, so it judges `rm -rf "$X"` without knowing what `$X` is. That is why it blocks.
- **Boundaries lost to compaction.** Conversation-stated boundaries ("don't push") can disappear with compaction. Durable limits belong in deny rules or hooks.
- **Cost and latency.** One classifier round-trip per non-read shell command. Billing impact is UNVERIFIED (see 2.7).
- **Allow-list drift.** An `autoMode.allow` entry is prose. Re-check it with `claude auto-mode critique` after each edit.
- **Self-Modification friction in claude-config and dotfiles work.** These repos *are* agent config and hooks, so the classifier will often want the change named. Expect more friction there than in app repos.
